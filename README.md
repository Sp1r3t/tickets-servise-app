# Ticketflow — микросервисная билетная платформа

Курсовой проект **«Разработка микросервисной платформы для продажи и бронирования билетов на концерты»**. React + TypeScript, пять отдельных сервисов Python/FastAPI, PostgreSQL для Docker-запуска, пять SQLite-файлов для локальной разработки.

## Что работает

- Афиша для зрителей: поиск по артисту/концерту/площадке, города, жанры, даты, цены и сортировка; после входа покупатель остаётся на афише, кабинет организатора доступен только организаторам.
- Регистрация покупателей и организаторов, вход по email/паролю, Argon2, короткоживущий JWT и обновляемая HttpOnly-сессия.
- Кабинет организатора: создание и редактирование черновика концерта, площадка, исполнитель, описание, постер по URL, время, возраст, контакты и условия возврата.
- Самостоятельный SVG-редактор: балконы/ярусы, поворот и изгиб рядов, сцена и объекты с произвольным контуром/эллипсом, перетаскивание вершин, столы, бары, колонны, лестницы, зоны и входы; 8 редактируемых основ (театр, клуб, арена, кинозал, джаз-клуб, банкет, подиум, амфитеатр), 12 форм, узнаваемые символы и варианты объектов. Инструменты сгруппированы по вкладкам; параметры выбранного элемента справа. Изгиб ряда меняется живым ползунком или ручкой на плане, соседние уровни видны бледной подложкой. Также: блоки рядов, отдельные места, сектора, номера, категории и цены, выделение рамкой/Shift, перемещение мест и сцены, доступные/заблокированные места, undo/redo, zoom, импорт/экспорт JSON, локальный черновик.
- Серверная проверка пересечений, границ, повторных номеров/ID и категорий. Ревизия защищает от перезаписи схемы другой вкладкой.
- Общая библиотека площадок: поиск по названию/городу/адресу, несколько вариантов схем, предпросмотр уровней, копирование в собственный редактор и заполнение площадки концерта. Опубликованные схемы автоматически попадают в библиотеку; частные черновики не публикуются.
- Публикация фиксирует снимок зала. У концерта появляется уникальная ссылка `/widget/{slug}` и код iframe для сайта организатора.
- Виджет: схема, цены, выбор до 8 мест, атомарная бронь на 10 минут, отображение оставшегося времени, отмена и **демонстрационная** оплата.
- Покупательский кабинет: заказы, электронные билеты с подписанным QR-кодом и печать через браузер.
- Однократная проверка билета организатором по тексту QR-кода, статистика проданных/забронированных мест и входов.
- Worker восстанавливает незавершённые заказы после сетевых ошибок; шаги Inventory и Payments идемпотентны.

**Реальные деньги не списываются.** OAuth, камера сканера, возвраты оплаченных билетов, рассылки и приложение пока не подключены. Границы MVP и следующий план описаны в [ROADMAP](docs/ROADMAP.md). Это проверенная учебная основа, ещё не готовый к коммерческому запуску сервис.

## Запуск через Docker

Нужны Python 3.12+ для генерации `.env`, Docker и Docker Compose.

```bash
python3 scripts/init_env.py
docker compose up --build -d
```

Откройте **http://127.0.0.1:8080**. Создайте аккаунт организатора, зал и концерт. PostgreSQL каждого сервиса имеет отдельный контейнер, пароль и volume; наружу открыт только сайт.

```bash
docker compose logs -f orders
docker compose stop
```

`stop` сохраняет базы. Удаление volumes удалит данные; обычный запуск этого не делает. Compose — локальная демонстрационная конфигурация. Миграции PostgreSQL выполняются перед стартом каждого сервиса.

## Локальный запуск без Docker

Нужны Python **3.12+**, Node.js **22+**, pnpm **11.25.0**. Если в PATH старый Python, укажите полный путь к актуальному интерпретатору.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock.txt
python scripts/init_env.py
python scripts/dev.py
```

Во втором терминале:

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Сайт: **http://127.0.0.1:5173**. API gateway: **http://127.0.0.1:8000/api/v1**. Остановка первого терминала завершает дочерние сервисы.

Можно собрать React и открыть всё на одном порту:

```bash
cd frontend
pnpm build
cd ..
python scripts/dev.py --built
```

Сайт: **http://127.0.0.1:8000**. Локальные базы создаются в игнорируемой папке `.data/`.

## Демо-данные

После локального запуска API выполните **явно**, если нужен готовый пример:

```bash
python scripts/seed.py
```

Создадутся зал на 112 мест и концерт на дату через 30 дней. Аккаунты:

| Роль | Email | Пароль только для локального демо |
|---|---|---|
| Организатор | organizer@example.com | DemoTicketflow2026! |
| Покупатель | buyer@example.com | DemoTicketflow2026! |

Скрипт повторно использует аккаунты и не меняет существующие концерты. Эти данные не создаются автоматически. Не применяйте их в публичной среде.

## Проверки

```bash
.venv/bin/ruff check services scripts tests migrations
.venv/bin/pytest -q
cd frontend
pnpm build
pnpm test:e2e
```

Playwright проверяет пользовательский путь, реальную HTTP-связь пяти процессов и мобильный размер окна. Для первого запуска браузера: `pnpm exec playwright install chromium`. По умолчанию E2E ожидает работающий сайт на порту 8000; адрес можно изменить через `E2E_BASE_URL`.

Тот же серверный набор запускается на PostgreSQL, если задан `TEST_POSTGRES_URL=postgresql+psycopg://…/postgres`. Тесты создают отдельные временные базы каждого сервиса и удаляют **только созданные ими базы**. Используйте выделенный тестовый PostgreSQL с правом CREATE DATABASE, не коммерческую БД. CI выполняет SQLite, PostgreSQL и браузерные проверки.

## API и структура

| Сервис | Локальный порт | OpenAPI |
|---|---:|---|
| Identity | 8001 | http://127.0.0.1:8001/docs |
| Catalog | 8002 | http://127.0.0.1:8002/docs |
| Inventory | 8003 | http://127.0.0.1:8003/docs |
| Orders | 8004 | http://127.0.0.1:8004/docs |
| Payments | 8005 | http://127.0.0.1:8005/docs |

Браузер общается только с gateway. Внутренние `/internal/*` маршруты наружу не проксируются. На машине без Docker сервисные порты доступны только loopback.
