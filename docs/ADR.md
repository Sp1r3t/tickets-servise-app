# Архитектурные решения

## ADR-001 — React/TypeScript и Python/FastAPI

Выбраны для быстрого развития визуального редактора, типизированных веб-компонентов и проверяемой HTTP API. FastAPI публикует OpenAPI, подходящую для будущих Swift/Kotlin/React Native/Flutter клиентов. Язык мобильных приложений пока не предопределён. Цена решения — раздельные TS/Python-контракты; перед мобильным этапом нужен генератор типов из OpenAPI в CI.

## ADR-002 — Пять сервисов, отдельные базы

Identity, Catalog, Inventory, Orders, Payments имеют разные бизнес-инварианты и профили нагрузки. Orders и выдача билетов объединены, чтобы завершать их одной локальной транзакцией. Разделение билетов в шестой сервис возможно позже, но сейчас добавит лишнюю saga. Дополнительные контейнеры gateway/frontend/DB не считаются микросервисами предметной области.

## ADR-003 — PostgreSQL как источник остатков

Продажа места нуждается в транзакциях, уникальности и row locks. Redis не используется как единственный резерв без долговечного учёта. SQLite — дополнительный режим локального запуска, не production-хранилище и не доказательство PostgreSQL-конкурентности.

## ADR-004 — Снимок концерта и ревизия шаблона

Зал переиспользуется, но концерт после публикации фиксирует схему и цены. Плата — нельзя просто редактировать опубликованное событие. Перенос/отмена будут отдельными процессами с аудитом и уведомлением зрителей. Ревизия шаблона защищает от конфликтов между вкладками.

## ADR-005 — Долговечная saga без брокера в MVP

Записанные состояния и идемпотентные команды обеспечивают восстановление после частичного сбоя. Polling снижает инфраструктурную сложность для курсовой. Недостатки: лишние HTTP-запросы и удержание локального lock во время сетевого шага. При росте нагрузки — lease, outbox/inbox и брокер; «exactly once» delivery не обещается, повторные команды обязательны.

## ADR-006 — Явный тестовый эквайринг

Можно показать полный цикл покупки без банковских данных. Демо не создаёт кассового чека, не списывает деньги и не обещает реальный возврат. Настоящий провайдер подключается только с серверной верификацией, idempotency, проверкой суммы/валюты и асинхронными состояниями возврата.

## ADR-007 — Минимальный пользовательский доступ

Работает email/пароль; социализация входа не эмулируется кнопками. Организатор пока равен одному владельцу событий. Следующая модель — organizations + memberships + права по ролям. Использование одного organizer JWT для всех сотрудников не допускается.
